# code-audit（存量代码覆盖审查）

召回率来自分镜头覆盖加机械化先扫，不是更仔细地通读。

## 流程

1. **圈定审查面**：模块/文件集 + 排除项。单文件或数百行内的小面直接审，不走本流程。
2. **机械化先扫**：测试、类型检查、lint 先跑；输入域宽的函数优先用 property-based-testing。机器能判的不占用审查注意力。
3. **写不变量清单**：这段代码必须满足什么（契约/守恒/顺序/资源配对）。审查变成逐条对表。
4. **分镜头并行审查**：按镜头派 fresh-context subagent，同一消息并行、互不可见。默认镜头：并发与状态 / 边界与错误处理 / 契约与不变量 / 资源与生命周期 / 输入假设；按代码性质增删，镜头间对象不重叠。每个镜头的 prompt 含：审查面、不变量清单、本镜头唯一负责的问题、证据分级要求（实测复现 > 路径推演 > 存疑）。
5. **汇总裁决**：去重、标严重度；每条给证据等级；高严重度项转 systematic-debugging 走根因流程；无法复现的进"存疑清单"明示。
6. **产出审查报告**：问题清单（按严重度）+ 存疑清单 + 已排除的整类问题（机械化覆盖的证据）。

## 红线（自检，踩了就重来）

- 单 agent 通读一遍就出结论 —— 审查面大时等于没审
- 镜头间互相可见结论 —— 锚定失效，退回重派
- 问题条目无证据等级 —— "感觉有问题"不入报告
- 跳过机械化先扫直接人工审查
