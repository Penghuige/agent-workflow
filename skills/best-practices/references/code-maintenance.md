# 代码维护约定

修改或审查代码时使用；行为保持不变的整理与行为修复分别审查和验证。

- 以修改局部性和职责边界判断结构，不按文件大小拆分；只为已出现的需求抽象。
  DRY 优先消除重复的业务知识，不强求合并相似语法或短小测试夹具。
- 共用能力归职责拥有者，跨模块调用使用明确接口；不让配置、存储等基础能力依赖具体业务流程。
  注释说明当前契约、限制和非显然的原因，迁移日期与任务过程留在历史记录。
- 删除兼容入口前查生产调用与存量数据契约；不只为旧测试保留接口。
  整理测试时保留可观察行为断言，不用函数身份或内部结构代替行为验证。
- 格式、导入等机械规范优先由已有工具配置检查。发现新问题先记录，不混入当前清理。
