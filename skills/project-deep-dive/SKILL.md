# project-deep-dive

## 执行

1. 从请求确定学习为哪种优化或产出服务；只有缺失的靶心会改变探索范围时才询问。读取已有学习笔记、版本和约束，从未决问题续接。
2. 摸清相关组件与主流程。探索可独立且有收益时交代码探索代理，否则自行读取；不为学习报告先做无关全库地图。
3. 还原关键决策：选了什么、放弃什么、当时约束及来源。优先查 git 历史、ADR/设计文档和注释；不存在的来源标为缺失，推测显式区分，不能只据当前代码断言历史原因。
4. 对影响学习靶心的决策查外部替代方法及适用条件；已有比较仍适用则复用。无检索能力时标明未覆盖，不凭记忆填补。
5. 输出决策清单：决策、取舍/约束、证据（文件:行号或原文来源）或推测、替代方法、可改造入口；附未决问题和下一步探测。

版本、证据和靶心未变时只补变化或缺口；先核对相关 diff 与资料适用范围，不重复派探索或重做外部比较。

## 笔记与交接

- 需保存时沿用项目约定；否则默认 `<工作目录>/notes/deep-dive/<项目>.md`。头部记录靶心、代码版本或日期、读取范围，正文使用上述清单。
- 沿用已批准的笔记写入范围；未获授权时先在回复交付内容并确认落盘，不能声称笔记已更新。
- 转交携带版本、约束、决策、证据路径、推测和未决问题。领域全景交 deep-research，高代价投入取舍交 deep-deliberation；仅继续用户已要求的任务。
- 后续实施或写作复用学习结果；本技能不自行把设计学习扩展为代码修改。
