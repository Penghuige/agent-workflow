# project-deep-dive（项目设计深潜）

## 流程

1. **定学习靶心**：从用户请求与现有上下文确定这次学习为后续什么优化/产出服务；仅在靶心缺失且会改变探索范围时询问。先读已有项目学习笔记、相关设计资料与已确认约束，从未决问题续接。
2. **方法与结构摸底**（派当前环境可用的代码探索 subagent，使用独立上下文；无此能力则自行探索并注明）：项目是什么、怎么分层、主流程如何走。此步从简。
3. **取舍还原**：列关键设计决策清单，逐条还原：选了什么 / 放弃了什么 / 当时约束是什么。证据优先级：git 历史与 commit 信息 > ADR/设计文档 > 代码内注释 > 社区讨论 > 推测（推测必须标注）。去历史与文档里找证据，不止读代码。某级来源不存在（如无 git 历史、非开源项目）则跳过该级并标注。
4. **替代方法图谱**：出项目找——同一问题还有哪些方法、别的项目怎么解、文献里的对应物，各注适用条件。无 web 检索能力时跳过此步并在笔记标注未覆盖。
5. **产出学习笔记** `notes/deep-dive/<项目>.md`（相对于发起会话的工作目录；项目文档有笔记目录约定则从之）：头部记学习靶心、代码版本（commit 或日期）、读取范围；正文为决策清单，每条 = 决策 / 取舍与约束 / 证据（附 `文件:行号`）或标注推测 / 替代方法 / 我若要改的入手点；末尾附未决问题与下一步探测。
6. **汇报**：结论与决策清单摘要，笔记路径附后。

已有笔记的代码版本、证据与当前学习靶心一致时，步骤 2–4 只补查变化或缺口；先核对相关 diff 与资料适用范围，不重复派探索任务或重做已有外部比较。

## 与其他技能协作

- 本技能负责还原一个项目的设计与取舍；领域全景调研交 `deep-research`，是否投入某种改造的高代价决策交 `deep-deliberation`。仅当当前任务需要时转交，不自动运行整套流程。
- 转交时提供学习靶心、代码版本或读取范围、决策清单、证据路径、推测、未决问题及可改造入口。下游沿用证据，仅补查新问题。
- 用户要求后续实现或论文写作时，沿用学习笔记推进其已授权任务；本技能本身不把设计学习扩展为代码修改。

## 红线（自检，踩了就重来）

- 产出目录导览/功能罗列当学习报告 —— 结构复述不是学习
- 取舍无证据也不标推测
- 只读代码不查历史与外部
- 没定靶心就开工
