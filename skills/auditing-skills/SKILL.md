# auditing-skills

## 选择范围

- 已有具体失败：定位触发、理解、执行或设计问题；真实失败记录可作为修复基线，不重新查生态或制造相同失败。
- 创建或修改后：按改动选择验证层级，见 [验证规则](references/validation.md)。纯格式做静态检查；改描述测选择；改流程测机制和行为，组合改动取并集。
- 用户要求全库体检：检查来源、入口、触发重叠和交接，不逐项运行全部技能。安装记录、可用插件与宿主目录一并考虑；无安装记录不代表原创，无触发史则记未知。

## 处理与交付

1. 先读现状、用户范围和已知失败；已有审查只复核变化与未决项。
2. 保留上游套件；来源不明且不在授权范围的技能只报告。复盘时给出与失败类型匹配的最小修复。
3. 只有诊断授权时交付问题与建议；已批准修改范围时备份、修复并完成对应验证，不重复请示。
4. 报告位置、证据、影响、处理结果和验证范围；明确未跑项。只有所需层级均通过才能称对应改动验证通过，不据样例承诺未来自动触发稳定。

## 协作

- 新建前查重用可用的 find-skills；编写用当前宿主的 skill 创建/编辑工具，不硬依赖未安装的名字。
- 交接保留任务范围、产物路径、已确认约束、证据与假设、未决问题；下游只补查需要的材料，不默认重跑整套流程。
- 遇到实际选择或交接失败再修对应边界；不因潜在重叠直接删改成套技能。
