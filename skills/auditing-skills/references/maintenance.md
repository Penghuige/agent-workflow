# 技能维护约定

## 新建与定向修复

新建技能前依次查本地、可用插件和网络；需要查重时使用宿主可用的 find-skills。
先读候选原文，已有能力满足需求时复用，不因名称不同另建一份。
已有自建技能的定向修复先查现状和失败证据，不重复生态查重。

## 来源与编写

上游套件保持原样；新增定制先明确归属，不能把无安装记录视为原创。
核对真实编辑源、宿主入口及发布副本，只同步获批范围，保留已有修改。

使用当前宿主可用的创建、编辑和验证工具；调用其他技能前核对可用性，
缺失时说明并在已有授权与角色边界内完成可做部分，不假定其他宿主的技能或路径可用。
用户已启用协作时，执行分工沿用已批准角色契约；本流程本身不启动多 agent 协作。

## 验证与交付

按 [分级验证](validation.md) 选择检查：纯格式做对应静态检查，改触发测选择，
改流程测机制与行为，组合改动取并集。结果与对应版本绑定，未跑分支明确列出。
技能部署按宿主可用的管理能力核对来源、文件入口与实际发现；不要用静态通过替代真实发现。
