# 按改动选择验证

| 改动 | 必需验证 |
|---|---|
| 标点、排版，不改变语义/链接/description | Tier 0 的对应格式检查 |
| description 或触发边界 | Tier 0 + Tier 2 |
| 指令含义、流程、输出或权限契约 | Tier 0 + Tier 1 + Tier 3 |
| 拆分文件或改引用，语义不变 | Tier 0 + Tier 1，实读引用验证可达；有流程变化再加 Tier 3 |

组合改动取并集；已通过的未受影响项目不重复运行。先记录本次修改前的真实失败或对照行为；纯整理只比较语义、引用与适用范围，不伪造行为失败。

## Tier 0：静态检查

- 检查 frontmatter、名称、引用可达与描述边界。描述简短且明确能力和何时使用，不重复正文流程。
- 同时看字节数、长行和重复内容；行数不是质量或加载成本的充分指标。多模式资料按需加载，短技能保留单文件。
- 指令只保留步骤、条件、动作和契约。理由的删除判据：删掉后遇到未覆盖情况是否会做错；会就留，不会就删。比喻、口号、重复解释删除。
- 安装或同步相关修改才检查宿主入口：实际解析路径、实体/链接、内容差异和来源，不为布局整齐新增重复入口。

## Tier 1：机制与引用

让干净上下文代理凭技能及其按需引用回答触发、反例、授权、材料复用或交付问题，覆盖本次变化；不预告期望答案。拆分资料时验证能找到所需内容，不强制读取全部引用。

## Tier 2：选择

另用干净上下文，只提供 descriptions 和场景，不提供技能全文。混入相邻技能，至少测正例、反例；改交接时增加组合任务。记录实际选择和依据，不只匹配关键词。普通调试不能因“卡住了”升级为高代价审议。

## Tier 3：行为

- 非编排型：独立代理拿真实或合成任务及原始材料完整执行，检查范围、证据、产物、授权与未决项。
- 编排型：主会话在隔离目录跑一轮，检查派发、独立上下文、汇总和实际产物。测试明确指定技能并说明模拟范围，不把日常低风险场景变成常规自动触发条件。
- 只验证改动影响的流程；明确区分合成样例与真实项目，使用最小足以暴露问题的材料。
- 按宿主容量分批，避免共享写入；能力不可用就记录该层未验证，不能以同上下文自审代替独立执行。

报告区分结构检查、选择测试、行为实跑与未覆盖分支；真实失败后定向修复并重测受影响项，不用多轮同样测试装饰通过结论。
