# decluttering-text

## 范围与模式

处理现有文本的审计、受控精简和深度改写：skill、规则文件、README、规格、发布说明、
代码注释、提交说明、错误消息和混合 Markdown。项目文风、术语表和用户本轮要求优先。

| 模式 | 允许改动 | 交付 |
|---|---|---|
| 审计 | 不改文件 | 发现表 + 保留不动 + 未检查 |
| 受控精简 | 客观问题 + 无歧义冗余；不重组结构、不改声音 | diff + 验证 |
| 深度改写 | 结构、段落顺序、术语统一、语气 | 先方案，批准后执行 |

用户只要求“检查/看看”时用审计；要“清理/精简/去味”且文件已存在时用受控精简；
要“重写/重构/大幅精简”时用深度改写。超过 5 个文件或预计改动超过 20% 行时，
先出方案或分批确认。

不处理：判断作者是否使用 AI、规避检测器、论文专项润色、翻译、从零写作、
代码行为修改、事实核查代替来源阅读。

交接：学术论文用 paper-polish / paper-writer / pre-submission-reviewer；
新写 agent 文档用 writing-for-agents；skill 结构与验证用 auditing-skills；
代码格式用项目 linter。

## 硬边界

1. **语义守恒**：事实、数字、否定、比较对象、范围、条件、时间、归因、确定程度和
   待办状态保持原样；`可能`、`约`、`待复核` 不是冗余。限定词跟随原命题，合并或
   换序后仍留在同一命题上。
2. **保护区可检查、不静默改写**：frontmatter、代码块、行内代码、命令、URL、路径、
   表格数据、配置、引语、数学公式和 i18n 占位符默认不改写；检查结果可以报告。
   `description` 审查是显式例外，改后必须跑 YAML 解析和 `skills-ref validate`
   （若可用）。
3. **AI 味只作提示**：词表、破折号、排比、问句标题、被动句、句长和格式都不是
   作者来源证据；只有降低读者价值时才改。
4. **最小有效修改**：能修一句不重写一段；能标注不猜测；可能改变含义、立场、
   承诺或作者声音的改动先列风险并确认。
5. **正向目标**：改写成读者需要的清晰文本，不以“看起来像人写的”或通过检测器
   为目标。
6. **证据先找替代**：时间戳、SHA、验证日志和临时路径先确认 Git/manifest 有
   等价记录；没有则保留或迁移，不默认删除。只删除纯叙事且已有替代证据的内容。
7. **默认跳过**：生成物、第三方代码、lockfile、minified 文件、二进制、密钥文件和
   不可读路径不编辑；报告跳过原因，不声称全量检查。

## 流程

1. **定界**：确认文件集、读者、用途、项目文风和模式；缺失信息会改变删改对象时
   才询问。
2. **列保留项**：记录事实与限定词、命令/链接/代码、授权边界、未完成待办、术语、
   数学/i18n 占位符和作者声音；它们构成改后核对表。
3. **先跑项目工具**：检查 `.markdownlint*`、`.vale.ini`、`.editorconfig`、
   Prettier/ESLint、测试和构建；有则先跑，按项目规则处理。没有时再进入下一步。
4. **跑本技能扫描器**：`python3 <skill-dir>/scripts/text_hygiene.py <paths>`；
   默认只在 error 时返回 1，`--fail-on warning` 或 `--strict` 才把 warning 当
   失败。warning 是线索，不是删除许可。用 `--exclude` 跳过生成物/笔记，
   用 `--summary`/`--json` 汇总。
5. **语义审查**：超过一个段落、跨文件或需要说明问题类别时读
   [patterns.md](references/patterns.md)，按 agent 可读性、人类可读性、AI 味
   弱信号、结构/语法和保留边界分组找问题。每条发现给出 `路径:行号`、
   原文摘录、影响、建议和风险等级。
6. **执行修改**：仅审计模式不改文件；受控精简只改客观问题和无歧义冗余；
   深度改写先给处理方案。批量文件按目录或类型拆分给干净上下文代理，
   每个代理只写自己的文件；合并时去重、复核保护区并裁决冲突。
7. **验证**：重跑扫描器和项目工具；Markdown/YAML/代码运行对应解析、测试或
   构建。逐条对照第 2 步保留项，确认没有语义漂移；无法验证的项目明确写出。

## 输出

- **审计**：先给总结，再给发现表（位置、证据、类别、影响、建议、风险），
  单列“保留不动”“误报候选”和“未检查”。
- **修改**：先列改过的文件和验证结果，再给关键 diff 摘要；凡可能触碰含义的改动
  单独列原文/改后/风险。用户要求可替换全文时只给最终版本；发现前一稿有误就直接
  修正，影响结论时在交付说明中记录。
- 不用字数下降、命中条数或“AI 味消失”作为完成标准；完成标准是读者能更快获得
  同一信息，且保留项逐项未变。

## 红线

- 把 `可能`、`约`、`待确认` 改成确定结论。
- 为执行词表而删除合法破折号、三项列表、问句标题、被动句、术语、作者强调或
  礼貌格式。
- 修改代码块、frontmatter、表格数据、命令参数、URL、数学公式或 i18n 占位符
  来迎合文风。
- 删除仍在跟踪的 TODO、警告、限制、授权边界或不确定性。
- 删除跨文件重复前未确认各文件是否会独立加载；能引用单一来源时引用，
  不能引用且读者需要自足时保留。
- 把“像 AI”当事实指控，或把扫描器 warning 当自动删除依据。
- 在生成物、第三方代码或密钥文件上执行改写。
