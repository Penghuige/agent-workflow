# 后台任务

负责进程生命周期。数小时级或无人值守任务的目标、预算与阶段计划由 long-task 管理；
跨 agent 的身份、送达、回传与验收由 agent-collaboration 管理。
仅在需要对应能力且宿主可用时交接；缺失时说明限制，并完成下面的进程登记与有界监督。

## 启动与登记

1. 按 cwd、关键参数、输入/输出路径和目标资源查重；已有同一任务先核对状态并复用。
2. 核实进程能否持续到任务结束。工具返回 session ID 或 tmux 存在都不能证明宿主退出后存活。
3. 在已有任务记录中登记下列信息；没有记录时才创建最小记录：

```text
任务标识/用途、拥有者、cwd；命令或输入版本：
PID/进程组或宿主任务 ID；日志、进度信号及最近有效进展：
预算/期限与停止条件（无约定则注明）；查询、停止及恢复方式：
通知能力、接收者及失败后的接手人（需要通知时填写）：
```

没有日志、进度或心跳等可观察信号时先补齐。开发期限、单次命令时限和通知等 ACK 的
期限各有作用，按任务契约分别记录；不把通知超时当成开发任务失败。

## 监控与交接

- 优先使用宿主完成通知；主动检查按有效进展退避，不只凭 stdout 静默、窗口 idle
  或总用时判定卡住/完成。异常先核对归属、进程、日志及最近有效进展。
- 当前轮等待会阻止所需完成通知时，交由 agent-collaboration 核对接单与路由后让出当前轮。
  不把持续轮询和等待该轮结束才能投递的回调组合成互等。
- 没有经验证的持续运行/通知能力时，采用当前轮有界监督或移交给明确接手人；
  报告任务 ID、状态、产物和查询/停止方式，不承诺后台自动监控。
- 恢复先核对原进程与产物；通知未达先查原记录，不重新启动同一任务。

## 收尾

完成、替换或会话结束时，只清理本会话拥有且获授权清理的监控与辅助进程，
核对其后代及任务记录。用户要求跨会话继续的任务保留，并交接当前状态、责任人、
产物位置、查询和停止方式；其他既有进程按用户的破坏性操作授权边界处理。
