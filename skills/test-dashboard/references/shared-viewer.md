# 多项目共用查看服务

需要在一个页面切换项目、报告变化后自动刷新时，优先复用已有 `test-dashboard`
本地服务。单项目离线交付继续使用 [项目接入与快照构建](project-setup.md)。

## 定位与启动

先查本机或工作区已有服务项目及 README。本机常用位置为 `~/github/test-dashboard`；
这只是安装位置示例，不是 skill 自带目录。找不到时说明缺失，再按当前任务范围处理。
已存在服务时不另建页面、复制模板或安装第二套报告解析器。

```bash
python3 ~/github/test-dashboard/run.py --engine-dir ~/.agents/skills/test-dashboard
```

服务 README 是启动参数和注册表格式的维护源。服务默认只绑定本机，前台运行，
按 `Ctrl+C` 停止。后台运行按宿主现有任务纪律查重、登记和交接。

## 接入与刷新

1. 复用项目已有 `.test-dashboard/config.json`；缺失时按项目接入说明初始化。
   注册前按项目接入说明盘点测试来源；列表中有项目不代表其测试过程已完整适配。
2. 在服务注册表添加唯一项目 ID 和该配置路径；同格式复用现有适配器。
   人工验收、矩阵与探索记录仍由项目采集器产出 v1 JSON，服务不执行采集器或测试。
3. 原生报告及其资源目录通过注册表显式配置；未生成 Trace 不声称轨迹可看。
4. 验证项目切换、报告变化刷新、缺失与解析错误、证据入口及实际数据量。
   服务自动刷新当前报告会重置筛选和弹窗；离线快照不随服务更新。

附件默认只读 HTML 输出目录，原生报告目录需显式登记。不要登记包含凭据或无关源码
的目录。浏览器断连保留旧画面时必须显示断连提示；坏来源保持采集失败，不能用旧的
成功结果冒充最新结果。摘要仅统计已采集用例，不据零失败推断全面通过。

## 引擎接口

服务通过可配置引擎路径调用 `scripts/dashboard_project.py` 的
`collect_project(config_path)` 和 `scripts/render_dashboard.py` 的
`render_html(document, output_dir, layout)`；两者均不落盘 HTML。
采集可能执行只读 Git 查询。引擎 Python 代码更新后重启服务；项目报告、配置和模板
变更由服务监听。原有 `init/build` 与直接渲染命令保留。
