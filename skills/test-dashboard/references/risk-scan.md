# 根据项目事实发现补测机会

先看当前架构、关键行为、不变量、输入域、外部依赖和已有测试证据，再选择相关问题轴。
以下用于检查遗漏，不是一律要执行的清单。项目明确不适用时记录依据；当前材料没覆盖
到某项，只能说“尚未见证据”，不能认定整个项目缺失。

需要细化输入域、规则组合、状态与故障时序，或选择宿主现有技能并交接证据时，读
[测试方法选型与阶段交接](testing-workflow.md)。已有结果接入沿用当前范围。

要求全面规划或判断各功能是否可用时，先做
[功能与证据对账](testing-workflow.md#功能与证据对账)，再将以下风险维度应用到各功能。
功能清单从需求和实际入口盘点；已有测试只用于对账，不能充当功能全集。

| 项目事实 / 风险 | 可考虑的测试 | 面板应保留的证据 |
|---|---|---|
| 解析、格式转换、计算、排序或大量输入组合 | 单元、边界、性质、模糊输入 | 输入/种子、实际与预期、最小反例 |
| API、模块接口或外部适配 | 集成、契约、负例、超时/重试 | 请求与响应摘要、错误码、依赖与运行环境 |
| 表单和用户任务流程 | 端到端、探索、可用性 | 真实步骤、前置状态、观察、截图/trace |
| 设计、键盘、屏幕或设备差异 | 视觉、可访问性、兼容性 | 比对基准、尺寸/浏览器、失败位置与截图 |
| 共享写入、重复请求、状态流转 | 并发、幂等性、状态不变量 | 参与者/顺序、重复条件、最终状态及中间证据 |
| 迁移、持久化和数据约束 | 迁移、事务、恢复 | 数据版本、测试数据、操作与恢复结果 |
| 负载、长任务或资源有限 | 性能、容量、稳定性/资源释放 | 实际负载、时长、环境、测量及停止条件 |
| 登录、权限、敏感数据或不可信输入 | 认证/授权负例、安全相关检查 | 允许的目标/账号、判据、脱敏证据 |
| 构建、安装、配置和部署方式 | 构建、启动、安装/升级、环境配置 | 实际命令、版本、输入配置与执行日志 |

针对选中的风险查已有用例、runner和结果，区分：已有且本轮有结果、已有但未运行、
仅有建议、待确认是否适用。没有可信用例清单时，不估算“还有N个未测”。

通过契约顶层 `methods` 展示已经考虑的方法及项目现状，用 `run_ids` 关联实际证据；
通过 `gaps` 交付具体补测建议：观察到的事实、潜在影响、方法、来源和置信边界。
优先列对本轮目标有影响的少量具体建议，不为覆盖表格堆满所有类别。
风险推测不是缺陷发现；测试通过也不证明所有相关风险均已消除。

实际执行新增测试或探索，沿用当前任务与项目授权；涉及新的环境、成本、破坏性操作
或外部动作时，先明确新范围。已批准的局部回归与检查直接推进，不因本参考重复审批。

宿主已提供适用的测试策略、性质测试、浏览器或领域能力时，按其 description 复用；
本 skill 负责将计划、执行与证据变成人能阅读的界面，不复制整套测试方法文档。
