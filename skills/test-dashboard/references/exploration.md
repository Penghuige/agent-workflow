# 开发后的探索记录

探索式测试围绕目标边学习边尝试；随机点击/输入、边界数据和不同操作顺序是可选手段。
采用已有测试器、浏览器工具或脚本，不为探索本身新增整套管理平台。

## 本轮输入与结束条件

从会话与项目约定复用目标、允许环境、操作范围、账号/合成数据、预算和停止条件。
只追问影响实际操作的未决信息；已有授权不重新确认。缺少可操作环境时可以完成页面
与数据接入，但实际探索应标为未执行，不拿假数据当真实发现。

将本轮目标写为简短 charter，例如：“在测试环境检查个人信息的修改、保存、刷新；
使用合成账号，预算15分钟，覆盖空输入/长文本/重复保存；不改变权限与外部系统”。
这些数值是例子，按任务设定，不作为每个项目的固定门槛。

## 实际执行与记录

1. 记录轮次、revision、环境、目标、工具和实际种子（如使用）。
2. 随执行追加实际动作与结果：页面/前置状态、可定位的操作、脱敏输入摘要、完成情况
   和观察。保留有因果关系的顺序；后续失败后没有执行的动作保持未运行。
3. 有截图、录像、请求错误或trace时关联到具体步骤；追踪敏感信息按项目规则处理。
   记录原始产物路径与来源，不能只在最后凭记忆补一段看似完整的回放。
4. 发现现象后，依据规范/断言/不变量判断；缺判据的体验疑点记候选发现，说明待确认
   的问题。按已批准范围复现并缩短操作路径，保留实际/预期与证据。
5. 结束时区分已探索范围、未探索部分、执行受阻和发现；清理本会话拥有的辅助资源。
   通过契约 `track=exploratory` 交付，不推断探索全集或整体完成率。

记录可映射到 [结果契约](result-contract.md) 的 steps、findings、attachments；每个
环境/重试/轮次保持独立身份。确认问题可转为计划轨的回归候选，保留原探索证据关联。
改产品、发消息、上传证据或触发新的执行范围，继续遵循当前任务授权。

## 框架接入

- Playwright：使用项目所装版本支持的步骤和报告器记录操作；需要页面状态、动作与
  网络定位时配置trace，并接原生查看器。录像和截图按项目策略采集。
- 其他框架：沿用已有步骤/附件机制；缺少轨迹能力时仍可交付真实动作日志和截图，
  明确能力缺口。JUnit式结果不自动包含浏览器操作。
- 面板消费归一化结果，不反向执行步骤文本；重放或重跑通过原测试执行器完成。

核对实际项目版本后查原文，不复制本参考中的示例命令作为跨项目事实：

- [Playwright TestStep](https://playwright.dev/docs/api/class-teststep)
- [Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer)
- [Playwright reporters](https://playwright.dev/docs/test-reporters)
- [Allure test steps](https://allurereport.org/docs/steps/)

这里只引用接入能力，不要求项目安装某个框架或外部报表平台。
