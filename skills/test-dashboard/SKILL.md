# 测试流程面板

本技能指导 agent 在项目环境内盘点测试流程、接入真实结果并维护项目适配，
通过共用界面展示过程与证据，辅助考虑相关测试方法及补测机会。
产出服务于人的判断：本轮范围是什么、已有何种证据、哪里失败或受阻、还缺什么、
下一步从哪个已有流程处理。默认复用中央模板与渲染器，项目只配置来源、分组和布局；
非标准结果由项目采集器转换为 v1 JSON，项目接入说明维护来源映射与刷新方法。

## 工作流

1. **识别项目与授权**：先读任务工作树的 AGENTS/CLAUDE 和相关约定，再查现有测试
   配置、用例清单、结果、报告、CI及可用查看方式。区分用户要求的查看、创建页面、
   刷新结果和实际探索；上下文已有范围与批准直接复用，仅询问会改变工作范围的缺失项。
   工作树、分支或来源不一致时先说明，不能把另一树的结果当成本轮证据。
   需要补充测试方法选型或阶段交接时，按需读
   [测试协作指南](references/testing-workflow.md)；只查看已有结果无需重走测试流程。
2. **确定两轨及证据范围**：计划轨接已有 TDD/验收清单与实际 runner inventory；
   探索轨接开发后真实尝试的操作、观察与发现。没有探索记录也保留清楚的空态。
   有结果不等于掌握项目全部用例；没有清单时总数与未测规模未知。按
   [项目风险与补测](references/risk-scan.md) 考虑相关方法，在方法总览展示已配置、建议
   补充、不适用及未评估项；通过实际 run 关联区分“考虑过”与“运行过”。建议与已实现
   测试分开记录；缺少评估不能显示为没有缺口。见下方两轨契约。
   用户要求全面规划、扩大覆盖或判断各功能是否可用时，按
   [功能与证据对账](references/testing-workflow.md#功能与证据对账) 盘点本轮功能与适用场景，
   交付功能→场景→用例→本次结果及缺口；仅有测试全绿不能完成这项判断。
3. **选择界面深度**：依据用例量、层级、运行时长、环境、重试与协作复杂度，在统一
   模板中选择布局与分组；具体取舍读 [界面适配](references/adaptive-design.md)。
   已有原生报告满足需求时沿用；保留其 trace、iframe 等查看能力及原始产物入口。
4. **接入并构建**：创建或刷新统一面板时，读 [项目接入](references/project-setup.md)，
   先完成来源盘点，再决定标准解析、项目采集或仅保留证据缺口；登记项目不等于完成适配。
   用中央 `init/build` 入口维护项目配置，默认不向项目复制或 fork HTML/CSS/JS。
   标准 Playwright/JUnit 报告走内置适配器；非标准输入写项目采集器，产出
   [v1 结果](references/result-contract.md)，再以 `normalized` 来源接入。
   不支持或缺失的来源显式列为未接入，解析失败显示采集失败，不得猜测成零失败。
   采集候选先按最终输出目录校验，再原子发布；检查来源状态，不能只看构建退出码。
   合法标准报告的兼容缺口优先修中央适配器，领域记录保留在项目采集器，不改写原始结果
   来迎合解析器。无中央修改权限时反馈最小样例与阻碍。
   需要一个页面切换多个项目、报告变化后自动刷新时，读
   [共用查看服务](references/shared-viewer.md)，复用已有服务及项目配置。
5. **核验实际行为**：运行范围内的解析/渲染检查，再打开页面检查两轨、失败下钻、
   筛选、空态、长文本、移动宽度和符合项目量级的数据。缺少步骤/附件、部分采集、
   不同环境、版本不匹配都要可见。改动涉及执行入口时验证真实任务状态，而非只验按钮。
   需要浏览器时使用宿主可用的 UI 测试能力；未执行项如实交付。
6. **交付与复用**：给出页面位置/查看方式、来源与本轮范围、已接入与未接入内容、
   实际验证及剩余缺口。项目适配、刷新命令与权限约定存于该项目已批准的位置；后续
   从现有约定续接，不把新项目的命令或角色写回通用 skill。

## 两条入口

两轨共同提供测试方法总览和缺口建议；分类由本项目事实决定，不固定一组测试种类。
界面展示是本技能主责；方法推荐是辅助，执行复用项目既有工具与当前已授权流程。

### 计划测试

展示已约定的测试/验收范围、已知用例、结果与已知未运行项，允许按层级/模块筛选。
TDD 的测试代码存在只说明有实现；本轮是否执行、覆盖了哪个 revision 和环境应单独取证。
有需求矩阵可关联“期望行为”，没有则如实留空。通过、失败、合法跳过、未运行分别展示；
未接入、采集失败和执行受阻是来源/执行状态。通过率不能替代覆盖率、完成度或发布判断。

两轨都可包含项目相关的任意测试类型，不固定为单测或浏览器流程；建议补测、已纳入计划
和不适用决定放在独立缺口区，保留依据与推测边界，不自动扩展执行范围。

### 探索测试

本轮也要求实际探索时，在已授权的目标与操作范围内明确本轮目标、数据、预算和停止
条件，复用项目探索能力并记录真实步骤。协议与例子见 [探索记录](references/exploration.md)。
没有实际探索授权时先做记录接入或待执行入口；不擅自对生产账号和数据开展随机操作。

每轮说明尝试过什么、发现什么、还有哪些未探索。可复现且有明确判据的问题与待确认的
可用性观察分开；一轮未发现已确认问题不表示项目已全面通过。将有价值的探索发现转为
后续回归候选，是否修改产品或纳入计划沿用户当前任务与项目规则处理。

## 点击用例后的详情

至少展示用例、所属轮次/环境、状态、来源及已采集的预期/实际/错误。有操作记录时依序
展示每步状态、失败位置和证据；截图、视频、日志及原生报告可导航查看。
探索记录额外展示目标、实际步骤、候选/已确认发现和判断依据。

trace 查看复用对应框架的查看器，按项目版本文档接入；没有录制就显示未采集。
不能从测试名编造操作录像、历史步骤或失败位置。普通离线详情与复杂 trace 查看能力
分别验收，不能承诺一个 HTML 解析所有框架的轨迹。

## 统一模板与执行入口

```bash
python3 <skill-dir>/scripts/render_dashboard.py --input results.json --output reports/index.html
```

已有 v1 输入仍可直接使用以上命令；中央渲染器与 `assets/dashboard.html` 生成无外部资源
依赖的双轨 HTML。`--layout` 可指定 `compact`、`grouped`、`workflow` 或 `auto`。
项目配置、多来源构建与快照版本见项目接入；字段和附件边界见结果契约。模板更新后需
显式重建快照，已生成的 HTML 不会自动更新。构建页面不运行测试、安装依赖或启动服务。

启动/重试优先接项目已配置、已批准的执行入口；记录命令、目标、进度和产物关联。
新增后台、权限系统、外部发布或持久服务先明确其成本及授权，不从“做页面”推导权限。
测试数据、日志和附件遵守项目隔离与脱敏要求；命令和结果文本按纯文本展示。
