# deep-deliberation（多视角对抗审议）

## 核心原则

单通道分析无论多聪明都只有一个框架。深度来自三件事：多个**目标函数不同**的视角独立作答（防从众）、一轮交叉批评（防自洽幻觉）、一份跨会话续接的前沿笔记（防从零重来）。

多视角的价值在**覆盖度与各司其职**，不在制造分歧：全视角一致只要是各轴独立得出的，就是合法结论，不为反对而反对。

证据优先级：机制/原始数据（含他人已发布的实测与计算） > 社区共识 > 趋势判断。下层来源可以佐证或提供线索，但不得单独支撑关键结论。

边界声明：所有视角来自同一基座模型，本质是"结构化自我批评"而非独立验证。条件允许且赌注足够高时，可混入异质模型（其他 CLI/API）做真独立视角（操作与安全规范参照 doubt-driven-development 的 cross-model escalation 节）。

成本：一轮 ≈ 视角数 + 1 次 subagent 调用（批评轮）；裁决证据可当场补取时再加取证调用。只用于值得的问题；用户明确说"快速聊聊"时退化为普通回答。

## 流程

1. **冻结问题**：先深化再写死——列出模糊点（真实决策对象、度量口径、各选项的具体配置、约束与期限、专名实例的角色：示例/锚点/基线、材料边界：本轮可调用哪些材料），每个模糊点附候选默认值，已有上下文足以明确决策时直接沿用；只有会改变决策对象或结论的关键信息缺失时才询问。用一两句话写死待审议的问题和赌注（stake），并列出选项空间（至少含"维持现状"和一个"第三选择"）。说给用户听后继续推进，不阻塞等回复；用户在派视角之前修正的，以修正版为准；视角派出后用户修正决策对象或关键约束的，受影响的视角在批评轮前重派，其余结论与证据继续复用。
2. **续接**：先查项目根 AGENTS.md / CLAUDE.md / README 有无笔记/文档目录约定，有则从之；否则笔记放 `<当前工作目录>/notes/deliberation/<主题>.md`。slug 由你起：小写英文连字符，粒度 = 一个可决策的问题（不是一个领域），跨会话不换。笔记存在先读，从上次边界继续；不存在则本轮建立。
3. **选视角**：从下方视角库选 4–6 个与问题类型最相关的（用户可指定/增删）。向用户说明选了哪些、各管什么——选视角的标准是问题轴的区分度，宁少勿重叠。
4. **独立分析**：先收集背景（用户提供的材料、相关文件、前沿笔记），整理成"已知事实 / 假设"清单。然后每个视角派一个 subagent，按可用并发容量分批派出，均使用干净上下文，互不可见；分批时不给后批视角传前批结论。没有 subagent 能力时，明确说明无法完成独立视角流程，可给临时分析，但不得声称完成本技能审议。每个 prompt 含：冻结的问题与选项空间、已知事实/假设清单、该视角的目标函数、职责约束（**只回答本轴问题**；跨轴发现用一句话标记"归 X 轴"移交编排者，不展开）。笔记含上轮结论时标注"此为上轮结论，你的任务是独立重审，可以推翻"。视角输出模板（五项，≤300 字）：结论 / 关键论据 / claim 边界（推测 vs 证据）/ 本轴解法（结论为否定时必填，一句）/ 所需背景信息清单。视角的跨轴发现与所需背景清单由你收集，随汇总一并交批评轮。每个视角的 prompt 还要显式指定信息获取方式（检索 / 读原始数据或文档 / 纯推理），视角间方法必须互异（视角多于三类方法时允许复用方法，但须错开对象，如分查官方文档与社区讨论）。科研场景优先使用当前可用的学术检索能力；没有专用数据源时，使用网页检索或公开论文接口，核对原文，不依赖某个固定连接器。
5. **交叉批评**：汇总各视角全文（连同冻结的问题、已知事实/假设清单、各视角的跨轴发现与所需背景清单），派一个批评 subagent，任务只有五样：矛盾地图（哪些结论互相冲突，逐对列出）、每个关键结论的最强反例、每条反对意见的反证路径（什么证据会推翻这条反对）、每个矛盾需要什么证据才能裁决及获取方式、关键引用抽查核实（读原文/对表，抓"各引半句"式失真）。批评轮之后，证据当场可获取的（读文件、跑命令）由你补取证；获取不了的进未决问题。
6. **综合 + 更新笔记**：由你按下文契约输出（选项空间来自第 1 步加视角产出中被提出的新选项）。综合时只采信被证据说服的论据。结论若为 delay / reject / 维持现状，先过一道反向检验："如果没做而结果错了呢？"再定稿。然后更新前沿笔记。

## 与其他技能协作

- 用户只要领域综述时由 `deep-research` 负责；只要具体想法的常规评价时由 `idea-evaluator` 负责。高代价取舍由本技能主导，不默认叠加它们的完整流程。
- 优先读取已有调研、评价和 `project-deep-dive` 笔记；传给视角时区分原始证据、已确认约束、旧结论和待验证假设，旧结论可被推翻。只补查影响当前裁决的证据缺口。
- 后续交接携带决策问题、约束、证据路径、已接受取舍、未决问题与下一步动作；不因提到其他技能就自动启动新任务。

## 视角库（每个视角独占一个目标函数；轴只是分组标签。选相关子集，不必全用）

| 轴 | 视角 | 目标函数（它唯一负责的问题） |
| --- | --- | --- |
| 值不值 | 长期价值 | 三年后谁在乎？价值随时间衰减还是复利？ |
| 值不值 | 机会成本 | 同样资源的最优替代用途是什么？ |
| 值不值 | 时机节奏 | 现在是对的时候吗？等待是否产生信息或期权价值？ |
| 行不行 | 工程可行性 | 成本/周期/依赖是什么？最小可行路径是什么？ |
| 行不行 | 风险可逆性 | 下行有多深？错了能回头吗？对冲是什么？ |
| 对不对 | 证据质量 | 哪些是推测、哪些有证据、验证方式可靠吗？该问题已有哪些现成方法/答案/思路可借鉴（不必有答案）？ |
| 对不对 | 对抗审查 | 最强反方论证是什么？什么条件下结论是错的？ |
| 对不对 | 历史一致性 | 与过去已否决/已决定的事冲突吗？是不是重复劳动？ |
| 简不简 | 减法 | 砍到什么最小版本依然成立？哪些是不必要的复杂？ |
| 影响谁 | 受众与二阶效应 | 谁会受影响、会怎么反应？激励会被怎样扭曲？ |
| 别处如何 | 类比基准 | 同类决策在其他领域的命运如何？有什么不随环境漂移的结构性教训？ |

默认组合：研究选题类 → 长期价值、机会成本、证据质量、对抗审查、历史一致性；工程决策类 → 工程可行性、风险可逆性、对抗审查、减法、受众与二阶效应。

## 综合输出契约（按此结构，一项不缺）

1. 冻结的问题（一句）
2. 结论，或"无法收敛 + 缺什么信息"；若为 delay / reject / 维持现状，附反向检验结果（没做而结果错了会怎样）
3. 各视角关键论据（每个 1–2 行）
4. 矛盾地图 + 每个矛盾的裁决证据
5. 被否决选项及否决理由
6. claim 边界：哪些是推测、哪些有证据
7. 下一步探测动作：一个可执行的小动作/小实验，附预期学到什么
8. 前沿笔记路径（已更新）

## 前沿笔记格式

```markdown
# <主题>
## 当前前沿（最近更新：YYYY-MM-DD）
- 结论：
- 未决问题：
- 下一步：
## 日志
### YYYY-MM-DD — <当轮问题>
（重审时先对照上轮"当前前沿"逐项标记 same / worse / resolved / new，
再写本轮：各视角结论摘要、矛盾与裁决、否决项、claim 边界）
```

每轮：更新"当前前沿"三节，日志追加一段，不删旧日志。

## 红线（自检，踩了就重来）

- 自己直接答完、没派视角 subagent
- 派视角前没收集背景、没给"已知事实/假设"清单
- 视角互相看得到结论
- 视角答非其轴、写成面面俱到的小论文 —— 退回重写
- 所有视角用同一方法获取信息（如全员检索）—— 退回做方法分工
- 视角输出缺 claim 边界或远超 300 字 —— 退回重写
- 跳过交叉批评直接综合
- 批评轮只有立场没有反证路径
- 答完没更新笔记
- 拿它回答日常问题 —— 直接答
